# 主板控制与反馈通信协议

更新日期：2026-10-22。实现工程：`D:\project\Paper\FR_Hand_m`。

## 1. 接口分工

| 接口 | 角色 | 波特率及引脚 |
|---|---|---|
| USART1 | 上位机MODBUS RTU；主板地址`0x10` | 230400，8N1；PA9 TX、PA10 RX |
| USART2 | 手指从板MODBUS RTU；目标地址`0x01/0x02` | 230400，8N1；PD5 TX、PD6 RX |
| CAN1 | 保留原有动作控制与心跳 | 1 Mbit/s；PA11 RX、PA12 TX |
| CAN2 | 接收两块从板角度、力反馈 | 1 Mbit/s；PB12 RX、PB13 TX |
| UART4 | 发送下述25字节汇总帧 | 230400，8N1；PC10 TX、PC11 RX |
| UART5 | 预留，当前无语音通信业务 | PC12 TX、PD2 RX |
| USART3、USART6 | 保留两个推杆电机控制 | 921600 |

源码保留`modbus2`作为上位机协议、`modbus1`作为手指总线协议的历史名称；它们现分别映射USART1、USART2。

## 2. CAN2反馈格式

仅接收标准数据帧。角度为16位大端、单位0.1°，范围0～900；每个力分量为8位、单位0.1 N，255表示25.5 N且是合法值。

| ID | DLC | 数据 |
|---|---|---|
| `0x020` | 8 | D0/1拇指motor0，D2/3拇指motor1，D4/5食指motor3，D6预留，D7序号 |
| `0x021` | 8 | D0/1拇指切向/法向，D2/3食指切向/法向，D4/5预留，D6 bit0/1为两传感器有效位，D7序号 |
| `0x030` | 7 | D0/1中指motor1，D2/3无名指motor2，D4/5小指motor3，D6序号 |
| `0x031` | 8 | D0/1中指切向/法向，D2/3无名指切向/法向，D4/5小指切向/法向，D6 bit0/1/2为有效位，D7序号 |

两板及角度/力帧分别更新时间和缓存，不强制序号相等。每种帧达到150 ms未更新则失效；力有效位清零立即生效。UART4发送时使用最新缓存，不触发从板采样。

CAN1原有命令可能与CAN2使用相同数值ID，软件按外设实例分流；CAN2反馈不会进入CAN1动作解析器。

## 3. UART4汇总帧

固定25字节：

```text
FF + 六路角度（12字节）+ 五路合力（10字节）+ 状态（1字节）+ AA
```

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xFF` |
| 1～2 | 拇指关节0 | 一号板motor0 |
| 3～4 | 拇指关节1 | 一号板motor1 |
| 5～6 | 食指角度 | 一号板motor3 |
| 7～8 | 中指角度 | 二号板motor1 |
| 9～10 | 无名指角度 | 二号板motor2 |
| 11～12 | 小指角度 | 二号板motor3 |
| 13～14 | 拇指合力 | 0.1 N |
| 15～16 | 食指合力 | 0.1 N |
| 17～18 | 中指合力 | 0.1 N |
| 19～20 | 无名指合力 | 0.1 N |
| 21～22 | 小指合力 | 0.1 N |
| 23 | 五指状态 | bit0～4依次对应拇、食、中、无名、小指；bit5～7为0 |
| 24 | 帧尾 | `0xAA` |

六路角度和五路合力都为无符号16位、大端，角度单位0.1°。未收到、无效或过期字段发送`0xFFFF`；力失效时对应状态为0。某块板失联不停止整帧发送。

合力按CAN分量重建：`F = sqrt(Ft² + Fn²)`，四舍五入到0.1 N；两个分量均25.5 N时，上报361，即36.1 N。从板已经量化和饱和造成的信息损失无法在主板恢复。

正文也可能含`FF`或`AA`。接收端须按固定25字节并检查第0和第24字节，不能直接按分隔符切包；本版不含CRC及序号，不提供严格的跨板时间同步保证。

默认10 Hz；当前波特率下每帧约1.085 ms，默认线路占用约1.09%。使用DMA普通模式发送整帧，UART4_TX使用DMA1 Stream4、Channel4；发送缓冲保留在普通SRAM，直到UART线路发送完成才释放。禁用半传输中断，正常每帧只产生DMA完成和UART发送完成两次中断；忙时跳过、不积压补发。停报时允许已经开始的一帧完整结束。

报文计算、25字节复制及DMA启动均在全局临界区外完成。配置写入和DMA启动共用带优先级继承的任务互斥锁，持锁不等待线路发送；仅在启动期间短暂屏蔽UART4自身的DMA中断，以关闭HAL默认半传输通知，其他中断继续响应。读取寄存器和反馈快照仍使用短临界区，保证同一帧使用一致数据；这不等于等待整帧发完。

DMA映射依据ST的[RM0090参考手册，DMA1请求映射表](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。DMA错误或20ms发送超时由上报任务终止发送；只有确认DMA已停止才允许再次覆盖缓冲区。

## 4. 五指状态规则

每指共用比值阈值`R`（默认1.0）和合力门槛`Fmin`（默认3.0 N）：

```text
数据有效且未过期，且Ft > 0，且F >= Fmin，且Fn / Ft < R：bit = 1
其他情况：bit = 0
```

合力门槛只影响状态，不把上报合力清零。比值等于阈值时为0，合力等于门槛时允许继续判断。计算用原始量化分量的平方和判断门槛，避免把四舍五入后的显示值当作真实比较值。

## 5. 新增MODBUS寄存器

地址为报文中的0起始地址，均为可读写16位保持寄存器。

| 地址 | 数组 | 用途 | 默认值 | 可写范围 |
|---|---|---|---|---|
| `0x001E` | `Reg[30]` | UART4使能 | `0x0001` | 0关闭、1开启 |
| `0x001F` | `Reg[31]` | UART4频率 | `0x000A` | 1～100 Hz整数 |
| `0x0020` | `Reg[32]` | 法向/切向比值阈值×10 | `0x000A` | 0～65535 |
| `0x0021` | `Reg[33]` | 合力门槛×10，单位0.1 N | `0x001E` | 0～65535 |

支持`0x03`读、`0x06`写单个、`0x10`写多个。`0x000A=1.0`、`0x0010=1.6`、`0x001E=3.0`，均为普通二进制整数，不是BCD。寄存器数值高字节在前，CRC沿用原工程的MODBUS实现。

例如：主板地址`10`，关闭上报的请求主体为`10 06 00 1E 00 00`，末尾由上位机追加MODBUS CRC；开启时把数值改成`00 01`。写`00 1F=00 14`表示20 Hz；写`00 20=00 10`表示比值阈值1.6。

一帧写多个值时先校验全部值，出现非法值整帧拒绝。使能只接受0/1，频率只接受1～100。阈值完整16位范围并不表示传感器具备该量程。

只读或只改上报配置不会触发手指分发、推杆位置命令或手腕启停。原控制区`Reg[4..8]`写入只通知一号板，`Reg[9..13]`只通知二号板。推杆控制区和手腕控制寄存器继续保留。

配置仅存RAM，重新上电恢复默认。UART4频率不改变从板CAN上报频率；若以后降低从板CAN频率，应同时调整主板接收超时。
