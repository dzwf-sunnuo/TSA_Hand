# 主板串口分工、CAN2反馈与UART4上报改造计划

> 状态：用户已批准并实施，已编译，设备联调待用户进行。日期：2026-10-22。
> 执行说明：后续实现按任务复选框推进；采用代理执行时使用 `superpowers:subagent-driven-development`，本会话直接执行时使用 `superpowers:executing-plans`。本次按用户要求直接实施，不运行编译以外的测试。

**目标：** 主板通过USART1接收上位机MODBUS命令，通过USART2控制两块从板，通过CAN2接收反馈，并通过UART4定时发送六路角度、五路合力和五指状态。

**架构：** 控制链路沿用MODBUS，反馈链路使用CAN2。CAN2接收任务维护反馈缓存，独立UART4上报任务按配置读取缓存并编码，不在接收中断中计算合力或发送串口数据。

**技术栈：** STM32F407、STM32 HAL、FreeRTOS/CMSIS-RTOS2、C、现有CMake工程。

**需求依据：** 本文记录用户已批准的方案；最终追加0xAA帧尾。实现记录与对外接口以本文及docs/Master_Feedback_Protocol.md为准。

1. CAN1控制与CAN2反馈出现相同数值ID时，反馈不得进入动作解析器。

## 一、需求规格

### 1. 串口与CAN分工

| 接口 | 目标用途 | 当前引脚 | 当前工程波特率 |
|---|---|---|---|
| USART1 | 上位机MODBUS接口，主板作为从机，地址`0x10` | PA9 TX、PA10 RX | 230400 bit/s，8N1 |
| USART2 | 两块手指从板MODBUS接口，主板作为主机 | PD5 TX、PD6 RX | 230400 bit/s，8N1 |
| CAN2 | 接收两块从板的角度、指尖力自动上报 | PB12 RX、PB13 TX | 1 Mbit/s |
| UART4（需求中的USART4） | 汇总反馈输出 | PC10 TX、PC11 RX | 230400 bit/s，8N1 |
| UART5（需求中的USART5） | 保留，后续可能连接语音上位机 | PC12 TX、PD2 RX | 当前初始化为230400 bit/s，本次不增加业务 |
| USART3 | 第一推杆电机，保留 | PD8 TX、PD9 RX | 921600 bit/s |
| USART6 | 第二推杆电机，保留 | PC6 TX、PC7 RX | 921600 bit/s |

串口波特率沿用当前源码配置；本次新增可配项只有UART4上报频率，不增加串口波特率寄存器。

目标数据流：

```text
上位机 ──USART1 / MODBUS──> 主板 ──USART2 / MODBUS──> 一号板、二号板
                                  ↑
                         CAN2 / 1 Mbit/s反馈
                                  │
                             两块从板

主板反馈缓存 ──默认10 Hz──> UART4：25字节汇总帧
主板原有动作控制 ──USART3、USART6──> 两个推杆电机
```

### 2. CAN2接收协议

沿用两块从板当前固件的标准数据帧，不改变从板帧格式，也不增加CAN广播查询协议。

| 从板 | 内容 | 标准ID | DLC | 字节定义 |
|---|---|---|---|---|
| 一号板`0x01` | 角度 | `0x020` | 8 | D0/1拇指motor0；D2/3拇指motor1；D4/5食指motor3；D6预留0；D7序号 |
| 一号板`0x01` | 力 | `0x021` | 8 | D0拇指切向；D1拇指法向；D2食指切向；D3食指法向；D4/5预留0；D6有效位；D7序号 |
| 二号板`0x02` | 角度 | `0x030` | 7 | D0/1中指motor1；D2/3无名指motor2；D4/5小指motor3；D6序号 |
| 二号板`0x02` | 力 | `0x031` | 8 | D0中指切向；D1中指法向；D2无名指切向；D3无名指法向；D4小指切向；D5小指法向；D6有效位；D7序号 |

- 角度：无符号16位，大端，0～900表示0～90.0°。
- 力分量：无符号8位，单位0.1 N，255是合法的25.5 N；超过25.5 N已由从板饱和。
- 一号板力有效位：D6 bit0拇指、bit1食指；二号板：D6 bit0中指、bit1无名指、bit2小指。
- 两块板序号独立，均按8位自然回绕；同一块板同轮的角度、力共用序号。
- 一号板motor2不在角度反馈中，本次UART4也不上报该自由度。
- 用户已把主从板CAN改为1 Mbit/s。当前三个工程的`can.c`均为分频3、BS1=10TQ、BS2=3TQ，PCLK1=42 MHz时：`42 MHz / [3 × (1 + 10 + 3)] = 1 Mbit/s`。旧注释或旧文档中的875 kbit/s不作为本次目标。

### 3. UART4汇总帧：已确认25字节

固定长度、二进制发送。字段顺序如下，字节偏移从0开始。

| 偏移 | 长度 | 字段 | 编码 |
|---|---|---|---|
| 0 | 1 | 帧头 | 固定`0xFF` |
| 1～2 | 2 | 拇指关节0角度 | 一号板motor0，无符号16位、大端、0.1° |
| 3～4 | 2 | 拇指关节1角度 | 一号板motor1，无符号16位、大端、0.1° |
| 5～6 | 2 | 食指角度 | 一号板motor3，同上 |
| 7～8 | 2 | 中指角度 | 二号板motor1，同上 |
| 9～10 | 2 | 无名指角度 | 二号板motor2，同上 |
| 11～12 | 2 | 小指角度 | 二号板motor3，同上 |
| 13～14 | 2 | 拇指合力 | 无符号16位、大端、0.1 N |
| 15～16 | 2 | 食指合力 | 同上 |
| 17～18 | 2 | 中指合力 | 同上 |
| 19～20 | 2 | 无名指合力 | 同上 |
| 21～22 | 2 | 小指合力 | 同上 |
| 23 | 1 | 五指状态 | bit0～4依次为拇、食、中、无名、小指；bit5～7固定0 |
| 24 | 1 | 帧尾 | 固定`0xAA` |

帧长：`1 + 6 × 2 + 5 × 2 + 1 + 1 = 25`字节。

默认10 Hz，即每100 ms发一帧。按当前230400 bit/s、8N1计算，每帧线路时间约`25 × 10 / 230400 = 1.085 ms`，默认发送占用约1.09%。这里仅计算UART4发送线路时间。

用户追加要求：末尾增加`0xAA`；本版不增加序号、CRC。正文也可能出现`0xFF`或`0xAA`，接收端应按25字节并检查头尾，不能按任意头尾字节切包；头尾标记不提供CRC级别的完整性校验。

### 4. 合力来源与精度

从板目前只通过CAN发送切向力`Ft`和法向力`Fn`，因此本计划按下式在主板重建合力：

```text
F = sqrt(Ft² + Fn²)
UART4合力原始值 = round(F × 10)
```

这里的输入是CAN已经量化为0.1 N、并可能饱和的分量；主板无法恢复饱和前的真实力值。若两个分量都是25.5 N，重建合力约36.06 N，上报361表示36.1 N，使用2字节可避免再次截断到25.5 N。

合力字段始终上报有效合力，不因状态位为0而清零。3.0 N门槛只参与状态判断。

### 5. 状态字节的规则（偏移23，倒数第二字节）

五根手指分别独立判断，共用一组阈值；每根手指对应一个bit，不是为法向力和切向力各分配一个bit。

设`R`为法向力/切向力阈值，默认1.0；`Fmin`为强制状态置零的合力门槛，默认3.0 N。

```text
若该指力数据无效或接收过期：对应bit = 0
否则，若Ft = 0：对应bit = 0
否则，若F < Fmin：对应bit = 0
否则，若Fn / Ft < R：对应bit = 1
否则：对应bit = 0
```

- “小于”均为严格小于；`Fn / Ft = R`时置0，`F = Fmin`时继续判断比值。
- 比值方向固定为“法向/切向”，不得写反。
- 食指为bit1，即用户所说的第2位。
- 不添加滞回或消抖，避免改变当前要求的阈值含义。

建议用CAN原始量化整数直接判断，避免除零和浮点比较误差：

```text
T10、N10：CAN力字节，分别表示Ft × 10、Fn × 10
R10：比值阈值寄存器，表示R × 10
Fmin10：合力门槛寄存器，表示Fmin × 10

置1条件：有效且未过期
          且T10 > 0
          且N10² + T10² >= Fmin10²
          且10 × N10 < R10 × T10
```

乘法先提升为至少32位无符号数。门槛比较使用平方和，不使用已四舍五入的UART4合力字段，以免2.98 N先显示为3.0 N后被错误放行。

默认阈值的示例：

| Ft / N | Fn / N | UART4合力 / N | 状态bit | 原因 |
|---|---|---|---|---|
| 4.0 | 2.0 | 4.5 | 1 | 合力足够，法向/切向=0.5，小于1.0 |
| 4.0 | 4.0 | 5.7 | 0 | 比值等于1.0 |
| 2.0 | 1.0 | 2.2 | 0 | 合力小于3.0 N |
| 3.0 | 0.0 | 3.0 | 1 | 合力等于门槛，比值0，小于1.0 |
| 0.0 | 4.0 | 4.0 | 0 | 切向力为0 |

### 6. MODBUS新增配置

以下默认值和缩放已由用户提出；地址和允许范围是本次实现建议。

| 数组索引 | 线缆寄存器地址 | 名称 | 默认值 | 单位与建议范围 |
|---|---|---|---|---|
| `Reg[30]` | `0x001E` | UART4上报使能 | `0x0001` | 0关闭、1开启；其他值拒绝 |
| `Reg[31]` | `0x001F` | UART4上报频率 | `0x000A` | 整数Hz，建议1～100；停报使用使能寄存器 |
| `Reg[32]` | `0x0020` | 法向/切向比值阈值 | `0x000A` | 无符号16位原始值×0.1，建议允许0～65535，即0～6553.5 |
| `Reg[33]` | `0x0021` | 状态置零的合力门槛 | `0x001E` | 无符号16位原始值×0.1 N，建议允许0～65535，即0～6553.5 N |

- 地址均为MODBUS报文中的0起始地址，不是40001等软件显示编号。
- `0x000A`是十进制10，表示1.0；`0x0010`是十进制16，表示1.6；`0x001E`是十进制30，表示3.0。均为普通二进制整数，不是BCD。
- 支持`0x03`读取、`0x06`写单寄存器、`0x10`写多个寄存器；寄存器本身按MODBUS规则高字节在前。
- 两个阈值允许完整16位范围是为了不擅自限制用户的可配值，不代表传感器具有该量程。
- 配置保存在RAM，重启恢复默认值；本次不新增Flash掉电保存需求。
- UART4频率与两块从板CAN频率独立；修改主板UART4频率不修改从板采集频率或CAN上报配置。

当前主板`Reg[0..17]`已有控制用途，`rs485.h`还定义了PID区`Reg[20..28]`；本计划建议使用`30..33`，不占用这些区域。主板`Reg[32]`与CAN ID`0x020`属于不同协议命名空间。

配置生效规则建议：

1. 写入先校验整帧、地址、数量、数据字节数及所有配置值，再一次性提交；多写帧中有非法值时不部分修改。
2. 使能或频率变化后唤醒UART4任务，重设周期基准，不补发错过的旧周期。
3. 关闭后不再启动新帧；已经在线路上发送的完整帧允许发完，避免截断。
4. 阈值变化最迟在下一帧生效；同一帧五指使用同一份配置快照。
5. 只读寄存器、只写`30..33`均不得触发从板命令分发、推杆位置发送或手腕启停。写入同时覆盖控制区和配置区时，按实际覆盖的控制寄存器触发对应控制路径。

## 二、实现建议与现有源码衔接

本节方案已由用户确认采用。以下涉及旧代码的描述为改造前问题，后续任务已落实对应改动。

### 1. CAN2反馈缓存与失效表示

- 只接收CAN2上的四个标准数据帧；校验IDE、RTR、ID、DLC。角度值大于900的对应帧不更新缓存。
- 为每块板分别保存角度、力数据、各自最后接收时间和序号；力有效位为0时立即把对应传感器标成无效，不能保留旧有效状态。
- 默认建议接收超时150 ms，按每种帧单独计时，适配当前从板默认20 Hz。判定采用无符号时间差，差值达到150 ms即过期。
- 若以后把从板CAN降到低于当前频率，须相应调整超时；只改变UART4上报频率不改变接收超时。
- 建议未收到、无效或过期字段在UART4中发送`0xFFFF`。角度、合力分别独立失效；力失效时对应状态bit强制0。`0xFFFF`不表示正常角度或6553.5 N合力。
- 不因一块板断线停止整帧发送；另一块板仍正常更新。
- 两种帧独立更新最新缓存，记录序号供诊断，不强制序号匹配后才允许使用，避免单帧丢失或角度无效停发时连带丢掉有效力数据。
- UART4打包时复制完整缓存快照，再离开短临界区计算与发送。不得边接收更新、边发送同一个缓冲区。
- 该汇总帧不承诺两块板、角度与力之间严格同步；它表示发送时各字段最近一次有效反馈。当前25字节格式不额外传送时间戳和序号。

### 2. CAN1与CAN2必须按总线分流

当前`Hardware/MyCan.c`启动、过滤和发送均固定使用`hcan1`。当前CAN回调把所有来源推入同一个动作队列，且消息结构没有总线来源字段。

现有CAN1命令使用`0x020`，源码也保留左手改用`0x021`的说明，恰好与一号板反馈ID重合。因此本计划保留CAN1原有控制入口，CAN2反馈走独立队列及解析路径：

- CAN1 → 原动作队列 → 原动作解析和推杆/手指控制。
- CAN2 → 新反馈队列 → 四类反馈解码和缓存。
- 共享HAL回调先按`hcan->Instance`分流，CAN2数据不得执行旧的`data[0]`动作分支。
- CAN1保留过滤器bank 0～13，CAN2使用bank 14～27，共同分界`SlaveStartFilterBank=14`；可在CAN2 bank 14以16位列表接收四个标准ID。
- 当前CAN2只有外设初始化，尚缺CAN2接收NVIC、中断入口、接收通知和业务启动；实现时补齐，并保持CAN1共享时钟有效。
- 中断只搬运帧、时间戳和统计，队列满时记录丢弃，不阻塞等待。帧长与格式校验后在任务中更新缓存。

### 3. USART角色互换须覆盖完整调用链

当前`Hardware/rs485.c`中`modbus2`是PC接口，但发送和接收实际使用USART2；`modbus1`是从板接口，发送使用USART1。

建议本次保留现有公开函数名以减少动作代码改动，但修正中文注释与串口映射：

- `modbus2`业务角色仍为“上位机MODBUS从机”，实际改用`huart1`。
- `modbus1`业务角色仍为“手指总线MODBUS主机”，实际改用`huart2`。
- PC初始化接收、DMA+IDLE回调识别、信号量命名、解析后的重新接收、异常恢复和回复发送全部一起迁移。
- `Host_write06_slave`、`Host_write16_slave`及单字节发送实际改用USART2。动作表和两从板地址不变。
- 当前两个USART均已配置RX/TX DMA；按现有资源迁移，不挪用推杆USART3/6的DMA资源。

### 4. MODBUS事件按实际命中范围触发

源码当前存在两处与新增配置直接相关的行为：

1. `Task_ModbusPC_Entry`每次收到事件后都释放`Sem_NewSlaveCmd`，并非只在有效控制写入时分发。
2. `modbus2_Event`末尾会根据`Reg[14]`发送推杆位置、处理手腕启停，与本次请求是否修改这些控制值无关。

实现时让解析结果区分“无效帧、只读、控制区写入、UART4配置写入”，在成功写入后按命中的地址范围触发副作用。校验失败、只读、配置写入均不重复执行动作；覆盖原控制寄存器的写入继续保留其原有控制能力。

保留`Reg[0..3]`对应的推杆目标/速度、`Reg[14]`的控制位、`Reg[15]`的周期及相关现有控制行为；具体触发范围在实现时按这些寄存器之间的依赖关系处理，不能只机械检查最后一个写入地址。

同时校验接收最短长度、寄存器数组边界、`0x10`字节数及收发缓冲区容量，避免新增配置访问走入现有未限界路径。

### 5. UART4定时发送

- 新建独立上报任务，默认100 ms周期；支持建议的1～100 Hz，使用绝对周期基准与余数累计，避免`1000 / Hz`截断导致长期频率偏差。
- 建议采用UART4中断发送整帧，补齐UART4 NVIC、中断入口和发送完成/错误分流；本次无需新增UART4 DMA。
- 每次先取得配置和反馈快照，完成合力与状态计算，再组装25字节；TX缓冲区在发送完成前不得被改写或失效。
- 上一帧忙时跳过本周期并计数，不积压旧报告、不忙等；错误时释放发送状态，后续周期继续尝试。
- 任务优先级低于现有推杆运动任务，ISR中不做平方根、不调用阻塞串口发送。
- 当前`Task_DebugPrint_Entry`每秒向PC接口发`0x55`，应取消这类混入MODBUS线路的测试字节；UART4同样只发送完整二进制反馈帧，不混入调试文本。
- UART5不创建接收解析、发送或语音任务；可以保留用户已经生成的外设初始化。
